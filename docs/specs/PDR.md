# HealthCare 项目 PDR (Product Design Requirements) - v3.5 [2026-03-05 更新]

## 1. 项目定位与核心愿景
*   **定位**：从“监视器”转变为“生产力工具”的营养师 CRM（营养师高效工作助手）。
*   **核心理念**：
    *   **赋能优先**：帮营养师“省脑子”，而非给销售“上刑”。
    *   **行为驱动**：将复购建立在“产生效果”的基础上（吃完、吃好、补货）。
    *   **去中心化信任**：沉淀营养师个人的数字资产，建立中立且专业的客户关系。
    *   **全链路逻辑闭环 (Logic Closure) [v3.4 强化]**：系统内所有核心板块（库存、跟进、证据、素材、订单）必须基于真实底层数据支持。新增 **PDR 2.0 中心化策略引擎**，并统一 **产品库单位标准 (Unit Standardization)**。
    *   **CRM 级信息密度 (CRM-Grade Density) [v3.5 新增]**：UI 布局全面转向专业 CRM 风格，通过紧凑设计提升单页信息承载量，优化专业人员的操作效率。

## 2. 技术架构总结 (Technical Architecture) [v3.5 更新]
本项目采用 **前后端分离 + Serverless** 的现代化架构，确保在大陆网络环境下依然稳定高效：

### 2.1 核心三要素
1.  **数据库 (Database)**: **Supabase (PostgreSQL)**
2.  **代码存放 (Code Storage)**: **Gitee**
3.  **网页发布 (Web Publishing)**: **Cloudflare Pages**

### 2.2 逻辑闭环设计准则 (Design Principles) [v3.5 更新]
*   **数据驱动 (Data-Driven)**: 移除所有硬编码的模拟数据。
*   **逻辑中心化 (Centralized Logic)**: 所有干预逻辑、告警规则、静默机制统一封装在 `useTriggers` 核心 Hook 中。
*   **仿真实验室 (Simulation Lab)**: 为营养师提供“逻辑模拟器”，支持即时验证规则触发效果。
*   **单位闭环 (Unit Closure)**: 区分 **规格单位 (spec_unit, 如: 粒)** 与 **包装单位 (packaging_unit, 如: 瓶)**。财务结算与补货建议统一采用包装单位，确保逻辑严谨性。
*   **CRM 紧凑布局 (Compact CRM Layout) [v3.5 新增]**: 
    *   **信息密度优先**: 采用紧凑的 Grid 布局，减少大面积留白。
    *   **微型化组件**: 使用更小的字体 (9px-12px)、更窄的间距 (gap-3/4) 及精简的 Padding (p-3/4)。
    *   **专业视觉**: 强化数据展示，弱化装饰性元素，确保营养师能在一屏内获取所有关键业务指标。

## 3. 客户详情页：五大核心板块闭环 [v3.5 更新]

### 3.1 库存追踪 (Inventory Tracking) [v3.5 优化]
*   **闭环逻辑**: `校准库存 - (方案每日剂量 * 自校准以来的执行天数) = 实时余量`。
*   **CRM 布局**: 采用 **三栏式紧凑布局**，左侧为实时监控网格，右侧为决策看板与日志，大幅提升财务预测的直观性。
*   **功能**: 
    *   **实测校准**: 允许点击“校准”输入真实剩余量。
    *   **动态水位**: 基于 `last_calibration_date` 自动扣减库存。
    *   **财务预测**: 补货金额 **强制关联产品库** 价格。
    *   **单位校正**: 补货金额与订单数量统一显示为 **“每瓶/每件”** 价格。

### 3.2 跟进日志 (Follow-up Notes) [v3.5 优化]
*   **闭环逻辑**: 关联方案执行情况（`adherence_score`）与客户随访记录。
*   **CRM 布局**: **紧凑时间轴 (Compact Timeline)** 设计，移除冗余卡片边距，单页可显示更多历史记录。

### 3.3 检测证据 (Evidence Chain) [v3.5 优化]
*   **闭环逻辑**: `配方针对指标 <-> 检测指标变化`。
*   **CRM 布局**: **双栏证据对比看板**，强化“干预前后”数据的视觉对比。

### 3.4 营销素材 (Marketing Assets) [v3.5 优化]
*   **闭环逻辑**: 基于客户真实的“好转数据”或“对比证据”自动生成。
*   **CRM 布局**: **4 列紧凑网格 (Poster Grid)**，方便快速预览及批量分享。

### 3.5 订单记录 (Order Records) [v3.5 优化]
*   **闭环逻辑**: 将补货决策关联至真实的交易流水。
*   **CRM 布局**: **高密度数据表格**，精简行高，适配专业财务审计视角。

## 4. 营养师实战反馈优化 [v3.5 更新]
*   **药物冲突库**: 内置常见药物-营养素冲突规则（如：降压药 x 钾、抗凝药 x 维生素 K 等），辅助专业决策。
*   **产品库增强**: 新增 `price` 字段，使补货建议具备数据说服力。
*   **成分库关联**: 汇总看板实时解析成分名称与“针对指标”，建立“成分-效果-证据”的专业链条。
*   **生命体征监控**: 采用 **Compact Dashboard** 风格，将 12 个月的趋势与核心指标（RHR、深睡等）高度集成。

## 5. PDR 2.0 中心化策略引擎 [v3.3 新增]
为了解决逻辑碎片化问题，v3.3 引入了全新的 PDR 2.0 引擎：
*   **统一入口**: `useTriggers` 成为系统唯一的规则判定出口。
*   **核心判定算法**: 
    *   `Compliance (依从性)`: 自动计算连续断服权重。
    *   `Inventory (库存)`: 基于校准水位的动态耗损预测。
    *   `Symptom (体感)`: 捕捉 `trend_pivot` 突变与评分滑坡。
    *   `Growth (随访)`: 智能匹配方案执行周期的关键节点。
*   **全局静默机制**: 48 小时自动折叠非紧急告警，防止信息过载。
*   **仿真校验**: 支持输入 Mock 数据，实时观察引擎的“决策过程”。

## 9. 开发者操作指南 (Operation Guide) [v2.7 更新]
为了确保系统长期稳定运行，请遵循以下操作规范：

### 9.1 代码备份与版本控制 (Gitee)
每次完成重要功能开发后，必须将代码同步至 Gitee 仓库：
1.  **暂存**: `git add .`
2.  **记录**: `git commit -m "描述你的更新内容"`
3.  **推送**: `git push origin master`

### 9.2 网页发布与云端同步 (Cloudflare)
当需要更新线上网页（如 `healthcare-pro.pages.dev`）时，执行一键部署命令：
1.  **部署**: `npm run deploy`
    *   *注：该命令会自动执行构建 (build) 并通过 Wrangler 上传至 Cloudflare。*

### 9.3 数据同步说明 (Supabase)
*   **实时性**: 系统已集成 Supabase SDK，网页端的增删改操作会实时同步至云端数据库。
*   **离线容错**: 网络不稳定时，系统优先读写 LocalStorage，待网络恢复后尝试同步。
