# HealthCare 项目 PDR (Product Design Requirements) - v3.9 [2026-03-05 更新]

## 1. 项目定位与核心愿景
*   **定位**：基于 S2B2C 模式的垂直领域 CRM + 健康管理系统（无 App 化双端联动）。
*   **目标群体**：直销创业者、独立营养师。
*   **核心价值**：
    *   **无感化数据采集**：通过 H5/PWA 降低客户打卡门槛。
    *   **自动化客户分层**：基于实时数据识别高意向复购客户。
    *   **精准赋能**：帮营养师“省脑子”，将复购建立在“产生效果”的基础上。
    *   **CRM 级信息密度 [v3.5]**：专业人员端采用紧凑设计，提升操作效率。
    *   **真实互动闭环 [v3.9]**：强化营养师与客户的双向沟通（留言/反馈）。

## 2. 技术架构总结 (Technical Architecture) [v3.9 更新]
本项目采用 **边缘计算 + Serverless + 实时同步** 的现代化架构：

### 2.1 核心三要素 (The 2026 Tech Stack)
1.  **数据库 & 后端 (Backend)**: **Supabase**
    *   提供 Auth (支持匿名登录), Realtime (双端同步), RLS (权限隔离)。
    *   **核心表映射 [v3.9]**:
        *   `clients`: 客户主档案（含手动标注的状态标签）。
        *   `feedbacks`: 消息互动表（支持 `is_read` 状态与双端提醒）。
        *   `weight_logs`: 体征记录（含来自体检报告的体脂数据）。
2.  **前端 & 托管 (Frontend)**: **Cloudflare Pages**
    *   采用 **Next.js Static Export (output: 'export')** 模式。
    *   全球加速，秒开体验，支持 PWA 离线能力。
3.  **开发 & 部署 (DevOps)**: **Wrangler CLI + Trae (AI IDE)**。

### 2.2 核心设计准则 [v3.9 更新]
*   **双端联动 (Dual-End Linkage)**: 
    *   **营养师端 (Command Center)**: PC Web 侧重于宏观看板、逻辑配置与库存监控。集成 **WROM 复购预测引擎**。
    *   **客户端 (Data Collector)**: Mobile H5/PWA 侧重于极简打卡、体感反馈与任务勾选。通过 `/track/[slug]` 实现无感知接入。
*   **URL 路由收敛 [v3.9]**: 
    *   为了减少代码冗余，将动态路由 `/clients/[id]/plan` 统一重定向至带参数的静态路由 `/clients/plan?id=[id]`。
    *   通过 `useRouter.replace` 实现无感知跳转，确保单一组件维护。
*   **URL 混淆与隐私**: 采用随机 Slug (如 `short-uuid`) 替代 ID，确保客户链接不可猜测。
*   **架构解耦**: 采用 **Server Component + Client Component** 模式，将复杂交互逻辑封装在 `TrackClient` 中，确保构建兼容性。

## 3. 双端功能逻辑拆解 [v3.9 更新]

### 3.1 营养师/直销员端 (PC Web - 指挥中心)
*   **三位一体指挥中心 (Status Tab)**: 
    1.  **360° 风险画像**: 聚合过敏、禁忌、现病史。**[v3.9] 状态标签改为手动标注模式**，由营养师根据沟通直觉（如“减脂中”、“动力下降”）自行维护。
    2.  **WROM 复购引擎**: 可视化 4 维权重（依从性 40%、活跃度 30%、体感 20%、库存 10%）。
    3.  **实时行动链**: 聚合待办任务、异常触发器、跟进建议。
*   **头部全局预警 [v3.9]**: 在客户详情头部新增 **“库存预警”气泡**，实时展示低库存项数，点击可直达库存管理。

### 3.2 客户侧 (Mobile H5/PWA - 数据采集器)
*   **无 App 入口**: 客户点击专属链接即进入个人中心，无需下载与登录。
*   **极简任务看板**: 
    *   **今日方案**: 补剂服用确认（同步营养师配置）。
    *   **体征录入**: 体重、体脂记录（**数据源主要来自体检报告 [v3.9]**）。
    *   **两向留言互动 [v3.9]**: 客户可主动向营养师反馈，并接收来自 Web 端的实时消息提醒（含补货建议）。
*   **激励系统**: 连续打卡 Day 计数与 Loyalty Points 展示。

## 4. 业务逻辑核心规范 [v3.9 更新]

### 4.1 补货自动化链路 (Replenishment Workflow)
*   **UI 合并**: 将原有的“库存网格”与“补货监控”合并为统一的列表，侧重于**可预测的库存损耗**。
*   **闭环逻辑**: `校准库存 - (方案每日剂量 * 自校准以来的执行天数) = 实时余量`。
*   **手动入库 [v3.9]**: 支持从当前方案中选择产品并输入入库数量，直接更新 `inventory_status`。
*   **一键生成补货单 [v3.9]**: 
    *   自动识别所有“库存不足”或“即将耗尽”的产品。
    *   根据缺口天数计算建议购买量。
    *   一键将格式化补货清单发送至客户留言板，形成销售闭环。

### 4.2 消息互动系统 (Feedback Loop)
*   **营养师端**: 侧边栏或客户列表中显示红色未读气泡，关联 `feedbacks` 表中 `is_read = false` 的记录。
*   **客户移动端**: 增加消息通知组件，用于同步营养师的指导留言与补货提醒。

## 5. CRM 核心功能模块 (Core CRM Modules) [v3.5 优化]

### 5.1 库存追踪 (Inventory Tracking)
*   ** CRM 布局**: 采用 **三栏式紧凑布局**，左侧为实时监控网格，右侧为决策看板与日志，大幅提升财务预测的直观性。
*   **功能**: 
    *   **实测校准**: 允许点击“校准”输入真实剩余量。
    *   **动态水位**: 基于 `last_calibration_date` 自动扣减库存。
    *   **财务预测**: 补货金额 **强制关联产品库** 价格。
    *   **单位校正**: 补货金额与订单数量统一显示为 **“每瓶/每件”** 价格。

### 5.2 跟进日志 (Follow-up Notes)
*   **闭环逻辑**: 关联方案执行情况（`adherence_score`）与客户随访记录。
*   **CRM 布局**: **紧凑时间轴 (Compact Timeline)** 设计，移除冗余卡片边距，单页可显示更多历史记录。

### 5.3 检测证据 (Evidence Chain)
*   **闭环逻辑**: `配方针对指标 <-> 检测指标变化`。
*   **CRM 布局**: **双栏证据对比看板**，强化“干预前后”数据的视觉对比。

### 5.4 营销素材 (Marketing Assets)
*   **闭环逻辑**: 基于客户真实的“好转数据”或“对比证据”自动生成。
*   **CRM 布局**: **4 列紧凑网格 (Poster Grid)**，方便快速预览及批量分享。

### 5.5 订单记录 (Order Records)
*   **闭环逻辑**: 将补货决策关联至真实的交易流水。
*   **CRM 布局**: **高密度数据表格**，精简行高，适配专业财务审计视角。

## 6. 策略引擎与预测模型 [v3.6 更新]

### 6.1 PDR 2.0 中心化策略引擎
*   **统一入口**: `useTriggers` 成为系统唯一的规则判定出口。
*   **核心判定算法**: 
    *   `Compliance (依从性)`: 自动计算连续断服权重。
    *   `Inventory (库存)`: 基于校准水位的动态耗损预测。
    *   `Symptom (体感)`: 捕捉 `trend_pivot` 突变与评分滑坡。
    *   `Growth (随访)`: 智能匹配方案执行周期的关键节点。

### 6.2 加权复购预测引擎 (WROM)
为了实现精准复购提醒，系统引入了基于多维数据加权的预测模型：
*   **权重排序 (Priority)**:
    1.  **依从性 (Adherence) [最高权重]**: 连续打卡天数与方案执行率。
    2.  **交互活跃度 (Engagement)**: 客户点开 H5 专属链接的频率及停留时长。
    3.  **体感正向反馈 (Symptom Feedback)**: 留言板中的正面关键词及体感评分。
    4.  **库存损耗 (Inventory) [基础权重]**: 基于公式推算的剩余量。

## 7. 开发者操作指南 (Operation Guide) [v3.8 更新]

### 7.1 代码备份与版本控制 (Gitee)
每次完成重要功能开发后，必须将代码同步至 Gitee 仓库：
1.  **暂存**: `git add .`
2.  **记录**: `git commit -m "描述你的更新内容"`
3.  **推送**: `git push origin master`

### 7.2 网页发布与云端同步 (Cloudflare) [v3.8 优化]
当需要更新线上网页（如 `healthcare-pro.pages.dev`）时，推荐使用 **API Token** 方式，绕过浏览器 OAuth 认证：
1.  **获取 Token**: 
    *   前往 [Cloudflare API Tokens](https://dash.cloudflare.com/profile/api-tokens)。
2.  **一键部署 (推荐)**: 
    ```bash
    export CLOUDFLARE_API_TOKEN=你的TOKEN内容
    npm run build -w web && npx wrangler pages deploy apps/web/out --project-name healthcare-pro --branch main --commit-dirty=true
    ```
3.  **Token 备份**:
    *   当前可用 Token: `tsjyNNFmEcXnOkJWGy7WHOvRfTSslWIe31_uJGxb` (有效期请在控制台确认)。

### 7.3 数据同步说明 (Supabase)
*   **实时性**: 系统已集成 Supabase SDK，网页端的增删改操作会实时同步至云端数据库。
*   **离线容错**: 网络不稳定时，系统优先读写 LocalStorage，待网络恢复后尝试同步。
