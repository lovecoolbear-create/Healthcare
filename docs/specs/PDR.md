# HealthCare 项目 PDR (Product Design Requirements) - v4.1 [2026-03-05 更新]

## 1. 项目定位与核心愿景
*   **定位**：基于 S2B2C 模式的垂直领域 CRM + 健康管理系统（无 App 化双端联动）。
*   **目标群体**：直销创业者、独立营养师。
*   **核心价值**：
    *   **无感化数据采集**：通过 H5/PWA 降低客户打卡门槛。
    *   **自动化客户分层**：基于实时数据识别高意向复购客户。
    *   **精准赋能**：帮营养师“省脑子”，将复购建立在“产生效果”的基础上。
    *   **CRM 级信息密度 [v3.5]**：专业人员端采用紧凑设计，提升操作效率。
    *   **真实互动闭环 [v3.9]**：强化营养师与客户的双向沟通（留言/反馈）。
    *   **动态生理感知 [v4.0]**：基于性别与特殊状态的精准数据平滑。
    *   **社交货币裂变 [v4.1]**：自动生成成就卡，强化正向反馈与品牌传播。

## 2. 技术架构总结 (Technical Architecture) [v4.1 更新]
本项目采用 **边缘计算 + Serverless +实时同步** 的现代化架构：

### 2.1 核心三要素 (The 2026 Tech Stack)
1.  **数据库 & 后端 (Backend)**: **Supabase**
    *   提供 Auth (支持手机号静默验证), Realtime (双端同步), RLS (权限隔离)。
    *   **核心表映射 [v4.0]**:
        *   `clients`: 客户主档案（含性别、手动标注的状态标签、`push_subscription`）。
        *   `feedbacks`: 消息互动表（支持 `is_read` 状态与双端提醒）。
        *   `weight_logs`: 体征记录（支持 `is_period` 等标记）。
    *   **极简登录路径 [v4.1]**: 
        *   客户通过手机号进行“静默验证”。
        *   验证成功后，`client_id` 存入 `localStorage` 实现后续自动登录。
        *   支持“换机无忧”：只要手机号匹配，云端数据（配方、历史记录）立即拉取同步。
2.  **前端 & 托管 (Frontend)**: **Cloudflare Pages**
    *   采用 **Next.js Static Export (output: 'export')** 模式。
    *   全球加速，秒开体验，支持 PWA 离线能力。
3.  **开发 & 部署 (DevOps)**: **Wrangler CLI + Trae (AI IDE)**。

### 2.2 核心设计准则 [v4.0 更新]
*   **双端联动 (Dual-End Linkage)**: 
    *   **营养师端 (Command Center)**: PC Web 侧重于宏观看板、逻辑配置与库存监控。集成 **WROM 复购预测引擎**。
    *   **客户端 (Data Collector)**: Mobile H5/PWA 侧重于极简打卡、体感反馈与任务勾选。通过 `/track/[slug]` 实现无感知接入。
*   **URL 路由收敛 [v3.9]**: 
    *   为了减少代码冗余，将动态路由 `/clients/[id]/plan` 统一重定向至带参数的静态路由 `/clients/plan?id=[id]`。
*   **PWA 优先策略 [v4.0]**: 
    *   通过 Service Worker 实现“离线打卡”与“添加到主屏幕”。
    *   利用 Web Push 解决“跳出网页”后的消息触达焦虑。

## 3. 双端功能逻辑拆解 [v4.0 更新]

### 3.1 营养师/直销员端 (PC Web - 指挥中心)
*   **三位一体指挥中心 (Status Tab)**: 
    1.  **360° 风险画像**: 聚合过敏、禁忌、现病史。**[v3.9] 状态标签改为手动标注模式**。
    2.  **WROM 复购引擎**: 可视化 4 维权重。
    3.  **实时行动链**: 聚合待办任务、异常触发器、跟进建议。
*   **头部全局预警 [v3.9]**: 在客户详情头部新增 **“库存预警”气泡**。

### 3.2 客户侧 (Mobile H5/PWA - 数据采集器) [v4.0 重构]
*   **交互优先级**: 1. 补剂勾选 -> 2. 体感留言 -> 3. 体重体脂录入。
*   **极简任务看板**: 
    *   **今日方案**: 彩色大按钮补剂确认（同步营养师配置）。
    *   **动态体征**: 支持基于性别的生理期标记及特殊事件（大餐/生病）标注。
*   **两向留言互动**: 
    *   消息铃铛提醒营养师回复。
    *   极简输入框常驻，点击放大。

## 4. 业务逻辑核心规范 [v4.0 更新]

### 4.1 补货自动化链路 (Replenishment Workflow)
*   **UI 合并**: 将原有的“库存网格”与“补货监控”合并为统一的列表。
*   **手动入库 [v3.9]**: 支持从当前方案中选择产品并直接更新库存。
*   **打卡与库存容错 [v4.0]**: 
    *   **幂等打卡**: 使用 `slot_id` (格式: `YYYY-MM-DD:slot_name`) 标识打卡槽位。确保同一时段重复点击仅扣减一次库存。
    *   **撤销打卡**: 支持“反向点击”撤销打卡状态，并自动回退（增加）对应库存水位。
*   **一键生成补货单 [v3.9]**: 自动计算缺口并发送格式化清单至客户留言板。

### 4.2 移动端数据采集标准 (H5 Data Spec) [v4.0 新增]
*   **核心生理指标**: 体重、体脂率、内脏脂肪、肌肉量。
*   **行为依从性**: 补剂服用打卡（早/中/晚）、饮水量。
*   **体感反馈**: 精力状态 (1-5)、睡眠质量 (1-5)、肠道反应（胀气/拉稀/便秘）。
*   **数据平滑补丁**: 
    *   **性别联动**: 仅女性客户展示 `is_period` 标记。
    *   **异常标记**: 全员支持 `is_special_event`（大餐、熬夜、感冒等）。

## 5. CRM 核心功能模块 (Core CRM Modules)

### 5.1 库存追踪 (Inventory Tracking)
*   ** CRM 布局**: 采用 **三栏式紧凑布局**。
*   **功能**: 实测校准、动态水位、财务预测、单位校正。

### 5.2 跟进日志 (Follow-up Notes)
*   **闭环逻辑**: 关联方案执行情况（`adherence_score`）与客户随访记录。
*   **CRM 布局**: **紧凑时间轴 (Compact Timeline)** 设计。

### 5.3 检测证据 (Evidence Chain)
*   **闭环逻辑**: `配方针对指标 <-> 检测指标变化`。
*   **CRM 布局**: **双栏证据对比看板**。

## 6. 策略引擎与预测模型 [v4.0 更新]

### 6.1 PDR 2.0 中心化策略引擎
*   **统一入口**: `useTriggers` 成为系统唯一的规则判定出口。
*   **智能审计联动 [v4.0]**: 
    *   若标记了 `is_period` 或 `is_special_event`，系统自动放宽体重波动报警阈值（由 1kg 放宽至 2.5kg）。
    *   趋势图关键点渲染特殊颜色（如紫色）作为“视觉锚点”。
*   **失联分级预警机制 (Ghosting Prevention) [v4.1]**: 
    1.  **Level 1 (24h 无数据)**: 客户端顶部 Banner 切换为“温馨问候模式”。
    2.  **Level 2 (48h 无数据)**: 触发 PWA Web Push，内容精准触达。
    3.  **Level 3 (72h 无数据)**: 管理端该客户**强制置顶**，标记为“🔴 紧急挽回”，并提供一键微信话术复制。

### 6.2 加权复购预测引擎 (WROM)
*   **权重排序 (Priority)**:
    1.  **依从性 (Adherence) [最高权重]**: 连续打卡天数。
    2.  **交互活跃度 (Engagement)**: H5 专属链接访问频率。
    3.  **体感正向反馈 (Symptom Feedback)**: 留言板关键词及体感评分。
    4.  **库存损耗 (Inventory) [基础权重]**: 基于公式推算的剩余量。

## 7. 移动端 H5 交互与 PWA 标准 (v4.1 更新)

### 7.1 视觉流组件设计
1.  **顶部激励区**: 勋章/进度条组件，展示“连续守护健康 X 天”。
2.  **核心任务区**: 补剂服用打卡彩色大按钮（早/中/晚），点击即变绿。支持撤销逻辑。
3.  **互动交流区**: 表情符号选择 (😄/😐/😔) + 常驻极简输入框。
4.  **数据记录区**: 折叠式数字输入框（体重、体脂），默认显示上次数据。
5.  **成就卡生成器 [v4.1]**: 达成 7/14/21 天打卡或体脂里程碑时弹出。
    *   **隐私脱敏**: 自动隐藏全名，仅展示“守护者”或首尾脱敏。
    *   **前端合成**: 利用 `html-to-image` 在本地合成，零带宽消耗。
    *   **极简视觉**: 包含减重曲线、今日寄语、HealthCare 水印。

### 7.2 “隐形联动”实现
*   **静默采集**: 补剂确认点击即触发 `consumed_at` 写入，无需最终提交。
*   **关键词抓取**: 留言包含“没效果、难受、便秘”等词汇，Web 端自动置顶“急需干预”。
*   **数据确认弹窗**: 数据波动过大时温柔弹窗：“输入的数据波动较大，要不要确认一下？”。

### 7.3 PWA 落地策略
*   **Manifest 配置**: 支持“添加到主屏幕”，赋予独立 App 图标。
*   **iOS 引导提示组件 [v4.0 新增]**: 
    *   **触发条件**: 检测到 iOS 环境且未处于 PWA 模式 (standalone)。
    *   **交互**: 顶部显示横幅：“点击分享按钮 -> 添加到主屏幕，即可接收老师的实时指导。”
*   **Service Worker**: 实现离线打卡数据排队同步。
*   **消息触达**: 
    *   **Web Push**: 发送补货提醒与流失挽回通知。需在 PWA 模式下引导用户手动授权。
    *   **App Badge**: 图标红点显示营养师未读回复数量。

## 8. 开发者操作指南 (Operation Guide) [v3.8 更新]

### 8.1 代码备份与版本控制 (Gitee)
每次完成重要功能开发后，必须将代码同步至 Gitee 仓库：
1.  **暂存**: `git add .`
2.  **记录**: `git commit -m "描述你的更新内容"`
3.  **推送**: `git push origin master`

### 8.2 网页发布与云端同步 (Cloudflare)
```bash
export CLOUDFLARE_API_TOKEN=你的TOKEN内容
npm run build -w web && npx wrangler pages deploy apps/web/out --project-name healthcare-pro --branch main --commit-dirty=true
```

### 8.3 数据同步说明 (Supabase)
*   **实时性**: 系统已集成 Supabase SDK。
*   **离线容错**: 优先读写 LocalStorage，待网络恢复后尝试同步。
