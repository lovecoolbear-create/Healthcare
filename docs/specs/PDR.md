# HealthCare 项目 PDR (Product Design Requirements) - v2.0

## 1. 项目定位与核心愿景
*   **定位**：从“监视器”转变为“生产力工具”的营养师 CRM（营养师高效工作助手）。
*   **核心理念**：
    *   **赋能优先**：帮营养师“省脑子”，而非给销售“上刑”。
    *   **行为驱动**：将复购建立在“产生效果”的基础上（吃完、吃好、补货）。
    *   **去中心化信任**：沉淀营养师个人的数字资产，建立中立且专业的客户关系。

### 2.1 阶段一：营养师 Web 端工作助手 (Phase 1: Web Workspace)

    *   **平滑降级 (Graceful Degradation)**：[cloud.ts](file:///Users/blair/HealthCare/apps/web/src/services/cloud.ts) 已实现自动降级逻辑。当 [memfire.ts](file:///Users/blair/HealthCare/apps/web/src/config/memfire.ts) 中的云端配置为空时，系统自动切换至 LocalStorage 模式，确保开发不中断。

*   **国内基础设施 (Domestic Infrastructure) [v2.1 更新]**：
*   **定位**：营养师的高效作业平台，解决“记录乱、方案杂、追踪难”的核心痛点。
*   **核心功能**：
    *   **默认登录工作台 [v1.8 更新]**：营养师登录系统后，默认首页停留在 **Dashboard 工作台**，确保第一时间获取核心待办与业务指标。
    *   **全生命周期档案**：客户入伙、身体指标基线、既往病史、调理目标的一站式记录。
    *   **智能方案配置**：支持 SOP 模板快速套用，产品组合（剂量、频次、库存预设）的深度定制。
    *   **工作仪表盘 (Dashboard) 深度重塑 [v1.9 更新]**：
        *   **优先级排序**：**“今日干预待办”**板块置于 Dashboard 最顶部，确保高风险、高时效任务（如紧急干预、关键随访）处于第一视觉中心。
        *   **快速执行动作条 (Quick Access Bar)**：集成“一键提醒补货”、“待处理紧急干预”、“今日关键随访”、“方案调整任务”快捷键，支持锚点跳转至对应业务板块，缩短操作路径。
        *   **健康指标改善率 (Health Indicator Improvement) [v1.9 新增]**：
            *   **实时计算逻辑**：基于客户档案中的 `health_goal`（调理目标）关键词自动分类（血糖、肠道、体脂、睡眠）。
            *   **好转判定标准**：根据 PDR 设定，体感评分（精力/睡眠/情绪）>= 7.0 即判定为“已好转”。
            *   **公式**：改善率 = 该维度已好转客户数 / 该维度总调理目标客户数。
            *   **交互联动**：点击 Dashboard 上的指标条，可一键跳转至 **Reports 报表详情**。
        *   **高意向转化潜力卡片 (Conversion Potential)**：基于多维逻辑（手动标注、库存临界、体感高点）识别的“高意向转化清单”。
        *   **体感改善评分 (Feeling Improvement Metrics)**：聚合 `energy_score` 平均值，对比 5.0 基准线展示交付效果。
        *   **已激活规则统计**：实时显示“已开启 / 总规则”数量。
    *   **数据分析报告 (Data Reports) 深度增强 [v1.9 更新]**：
        *   **交付质量深度分析 (Delivery Quality)**：
            *   **多维下钻**：支持按血糖平衡、肠道微生态等维度查看详细的改善情况。
            *   **分客户明细**：清晰展示“已好转”与“待提升”客户名单，支持点击直接穿透至客户 360° 档案进行方案调整。
            *   **趋势可视化**：提供近 6 个月改善率趋势曲线（柱状图/折线图），直观评估营养师服务交付质量的波动与提升。
    *   **数据资产高效录入 [v1.7 更新]**：
        *   **标准 Excel/CSV 批量导入**：支持“产品库”与“客户档案”的大规模数据迁移。
        *   **三步走闭环工作流**：
            1.  **下载标准模板**：强制使用系统表头，确保数据对齐一致性。
            2.  **预览对齐与校验**：实时解析文件内容，对“必填项缺失”、“格式错误”、“手机号重复”等异常进行红色高亮提示。
            3.  **批次管理与撤回**：支持导入历史溯源，提供“一键撤回 (Rollback)”功能，确保误操作可物理级恢复，保护存量数据安全。
        *   **模板动态化 (Dynamic Templates)**：下载模板将基于当前 PDR 业务模型动态生成，自动包含最新扩展字段（如调理目标、产品分类等），确保录入维度与系统功能同步更新。
    *   **产品模型深度扩展 [v2.0 更新]**：
        *   **成分库管理优化 (Ingredient Library Optimization)**：
            *   **去中心化录入**：移除独立的成分库入口，成分直接在录入产品时配置。
            *   **支持自定义成分**：允许在搜索不到成分时，直接“添加新成分”并自动同步至系统全局成分库。
            *   **持久化同步**：通过 React Context + LocalStorage 实现成分库的自动保存与全局同步，为云端数据库接入做好架构准备。
    *   **智能方案配置 [v2.0 更新]**：
        *   **重构配方创建流程 (Recipe Creation Refactoring) [v2.2 更新]**:
            *   **动态管理**: 支持阶段 (Phase) 的灵活添加与删除。
            *   **二位一体模式**: 将每个操作设计为“添加产品（库选择）+ 添加使用方法”。
            *   **手动产品选择 [v2.2 新增]**: 移除自动添加逻辑，改为从产品库中手动搜索并选择产品。支持按名称、品牌、功效、分类进行多维模糊搜索。
            *   **产品移除功能**: 支持从已配置的方案中随时删除不需要的产品动作 (Action)，确保方案的精准迭代。
            *   **服用方法标准化 [v2.2 新增]**: 统一服用方法展示为“一日几次、一次几粒、服用时机”，支持直接在方案卡片中实时编辑并持久化保存。
        *   **深度使用方法定制 (Usage Method Customization)**：
            *   **服用频次** (`frequency_per_day`)：支持自定义每日服用次数。
            *   **单次剂量** (`dosage_per_time`)：支持字符串化输入（如 "1粒"、"5ml"），提供非标单位支持。
            *   **服用时机标签** (`timing_tag`)：预设“随餐 (With Meal)”、“空腹 (Empty Stomach)”、“餐前 (Before Meal)”、“餐后 (After Meal)”、“睡前 (Before Bed)”、“任意时间 (Any Time)”等标准化时段。
            *   **自定义备注** (`usage_instructions`)：支持为每个动作添加个性化使用建议。
        *   **方案贴条自动化**：一键生成脱敏的“调理方案贴条”，自动聚合产品、剂量、频次与时机信息，方便复制给客户。
    *   **代码与资产同步 [v2.0 新增]**：
        *   **GitHub 实时同步**：代码已托管至 GitHub，支持版本化追踪与协同。
        *   **LocalStorage 自动保存**：实现数据在浏览器端的自动持久化，确保营养师的操作数据不丢失。
    *   **客户档案 360° 扩展 [v1.7 更新]**：
        *   **调理目标 (Health Goal)**：明确客户核心诉求，作为方案制定的首要参考。
        *   **获客来源 (Source)**：记录客户转化路径，支持 Dashboard 来源分布看板，赋能销售转化分析。
    *   **全局干预触发器逻辑设计 (Logic Design) [v1.6 更新]**：
        *   **设计原则**：每一个触发器都是一条“如果 (Condition) ... 就 (Action) ...”的指令。
        *   **A. 条件池 (Condition Pool)**：调用核心数据实体。
            *   **库存维度**：`current_stock_count < X` (自定义阈值)。
            *   **行为维度**：`daily_adherence_log` 连续 N 天为 0（判定阈值已上调至 80% 依从性）。
            *   **体感维度**：`vital_trend_score` 连续 M 次下降（解决“吃了没感/难受”）。
            *   **时间维度**：距离方案开始已过 P 天（阶段性回访/商业增长）。
        *   **B. 动作池 (Action Pool)**：触发移动端任务或系统标记。
            *   **红点通知**：在营养师移动端生成一个“待办事项”。
            *   **模版推送**：自动选择一套话术（如：[补货模版]、[断服关怀模版]）。
            *   **状态标记**：将该客户在列表中的权重置顶（红色高亮）。
    *   **2.1.1 营养师 Web 端深度优化 [v1.6 新增]**：
        *   **全局导航标准化**：引入 `ActiveTab` 枚举统一管理 Sidebar、Dashboard 及 客户 360° 档案的导航状态，确保跨组件跳转的一致性。
        *   **触发器样式与语义对齐 (Alert Groups Alignment)**：将触发器划分为 `Compliance`、`Inventory`、`Symptom`、`Growth` 四大核心维度，并全面集成 `ALERT_GROUPS` 视觉标准。
        *   **360° 档案视图闭环**：确保抽屉内的库存、方案、笔记与全局触发器逻辑同步，提升数据准确性。
    *   **全局静默规则 (Global Silent Rule) [v1.4 新增]**：
        *   **逻辑**：同一客户在 48 小时内，最多只能触发 1 个非紧急（Non-Critical）红点告警。
        *   **目的**：算法自动合并同类项，防止多项触发器同时激活导致营养师端信息过载。
        *   **优先级**：紧急告警 (Critical) 不受此限，确保高风险事件第一时间触达。
    *   **智能任务引擎 (Task Engine)**：仪表盘告警不再是硬编码，而是基于上述触发器配置动态生成，支持按优先级（Critical/High/Medium/Low）自动排序。
    *   **人工库存校准 (Inventory Calibration)**：支持营养师手动修正剩余天数，确保提醒准确性。
    *   **生产力工具**：支持一键生成脱敏“好转海报”；多维 SOP 模板库自动匹配随访脚本。
    *   **交互逻辑**：营养师在 Web 端管理，初期通过导出图片/文本与客户同步。

### 2.2 阶段二：全链路移动端协同 (Phase 2: Mobile Ecosystem)
*   **营养师移动端**：聚焦“即时响应”。接收 Web 端触发的紧急预警，集成微信沟通，处理突发体感反馈。
*   **客户端 (Client Portal)**：极致轻量化的执行工具。
    *   **自动化打卡**：客户只需点击“已服用”，数据实时回传 Web 端。
    *   **库存校准**：系统估算与实际库存的动态同步。
    *   **可视化进度**：客户直观看到主观体感与客观指标的改善曲线。

#### **1. 极速对齐 (The Daily Action) - 客户每天必须做的 1%**
*   **智能打卡卡片**：系统根据方案自动弹出：“早起水 + 益生菌，已服用？”（3秒内一键完成）。
*   **库存同步弹窗**：每周一次，“系统估算你还剩 5 粒鱼油，实际还剩几粒？”（一键校准库存引擎）。
*   **体感微调研**：每天一个滑块，滑动选择“今日精力值 1-10分”。

#### **2. 好转进度条 (The Mirror) - 客户最关心的价值体现**
*   **双轨趋势图**：
    *   **主观线**：精力、睡眠、情绪的曲线变化。
    *   **客观线**：体重、腰围、皮肤对比照（支持隐私加密预览）。
*   **细胞修复进度**：科普化语言（如：“你已连续服用 Q10 十四天，心脏线粒体供能正在优化中”）。

#### **3. 数字化分身 (The Human Touch) - 让营养师“一直都在”**
*   **方案置顶**：当前的调理方案、禁忌食物清单、喝水目标。
*   **专业投喂**：针对该客户体质推送的短文（如：为什么你吃鱼油会打嗝？）。
*   **一键呼叫**：紧急情况直接触达营养师微信。

## 3. 健康改善报告逻辑 (Dual-Track Reporting)
### 3.1 主观感触轨 (Qualitative Feedback)
*   **适用场景**：睡眠、情绪、精力、消化等无法直接量化的体感改善。
*   **反馈频率**：高频（2-3天/次）。针对见效快的产品，系统自动在第 3 天提醒客户录入感受。
*   **报告形式**：文字叙述 + 营养师点评。由营养师驱动，捕捉即时体感变化。
### 3.2 客观指标轨 (Quantitative Tracking)
*   **适用场景**：减肥（体重/体脂）、血脂、血糖、尿酸等可量化的生理数据。
*   **反馈频率**：低频（周/月/季）。根据不同的身体状况设定周期。
*   **报告形式**：历史趋势图 + 异常预警。用硬数据说话，建立科学化管理的专业信任。

### 3.3 风险管理：负面反馈预警 (Risk Alert)
*   **逻辑**：若客户在“主观感触轨”连续 3 次反馈“无改善”或出现“不适/负面评价”，系统立即在营养师 Dashboard 触发**红色预警**。
*   **动作**：强制营养师介入（调整剂量、心理安抚或更换产品），防止潜在的客诉与流失风险。

## 4. 核心逻辑：库存校准引擎 (Phase 1 & 2 Evolution)
**原则：系统预警、人工/自动确认、营养师跟进。**
*   **触发机制**：系统根据（初始库存 - 累计打卡/预计消耗）计算剩余天数。
*   **预警节点**：剩余天数 ≤ 3-5 天时，自动进入 Dashboard “待补货”名单。
*   **分阶段交互动作**：
    *   **Phase 1 (Web 助手)**：营养师在随访时询问客户库存，在 Web 端点击“一键补货”或手动修改库存值。
    *   **Phase 2 (移动端协同)**：
        *   **外部引导**：系统提供“去购买”按钮，支持营养师配置外部跳转链接。
        *   **到货反馈 (Auto-Update)**：客户收到货后点击“确认收货”，系统自动更新 `current_stock`。
*   **核心价值**：防止客户因断货导致干预中断，提升复购率。

## 5. 随访小贴条 (Hybrid Tags System)
**解决“懒得记”与“记不准”的矛盾。**
*   **系统预设标签**：用于品牌方标准化数据分析（如：好转中、严重漏服）。
*   **个人自定义标签**：由营养师根据个人习惯自行创建。
*   **逻辑反哺**：标签状态（如“严重漏服”）会直接挂起或调整 Dashboard 的预警逻辑。

## 6. 服务逻辑：标准化 + 个性化 (SOP & Personalization)
*   **SOP 模版库**：系统预设针对不同病症/阶段的关怀与随访模版。
*   **营销素材沉淀**：**一键生成好转海报**。系统支持将客户脱敏后的“健康改善趋势图”或“好评记录”一键转化为适合朋友圈分享的匿名海报。
*   **个性化微调**：所有模版在发送前强制提供编辑入口，确保服务温度感。

## 7. Dashboard “五项军规” (带优先级逻辑) [v1.8 更新]
**核心逻辑：基于“成交意向”与“服务风险”智能排序。**
1.  **今日干预待办 (Intelligent Alerts)**：最高优先级。包含紧急反馈、今日关键随访、未完成方案调整。
2.  **高意向转化潜力 (High Potential)**：销售优先级。基于“准成交”标签、库存临界及情绪高点自动识别。
3.  **待补货提醒 (Replenishment)**：运营优先级。剩余天数 ≤ 触发器阈值的客户清单。
4.  **体感改善追踪 (Feeling Metrics)**：服务质量。实时聚合精力/睡眠/情绪数据，对比基准线展示交付效果。
5.  **干预规则池 (Active Rules)**：系统健康。透明展示已激活的规则数量与状态。

## 8. 数据安全与资产
*   **数字化健康档案**：主观体感 + 客观指标 + 随访记录，形成完整的客户全周期数据资产。
*   **所有权隔离**：多租户架构，保护营养师个人私产，同时支持品牌方查看脱敏后的服务报告。
