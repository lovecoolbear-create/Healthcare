# HealthCare Pro 项目核心规范 (PROJECT_SPEC.md)

## 1. 双端逻辑 (Dual-End Logic)
本项目中客户【仅使用手机 H5】，复购公式的所有【计算与展示】逻辑仅存在于营养师的 Web 管理端。

1.  **后端触发器**：请在 Supabase 的 `check_ins` 表上建立一个触发器（Trigger）或 Edge Function。每当客户在 H5 提交一次打卡，就自动更新 Web 端可见的 `renewal_score`。
2.  **数据隔离**：确保 H5 端的 API 请求极其轻量，只负责 POST 数据；所有的聚合查询（如计算过去 7 天平均分）都放在 Web 端或服务端完成，以保证手机端的加载速度。
3.  **视觉差异**：H5 端的重点是『激励与美感』，Web 端的重点是『数据与颜色预警』。
4.  **身份锚定**：以 **手机号** 为唯一物理 ID。换机登录后，必须通过手机号从 Supabase 完整恢复历史记录。
5.  **数据隔离 (RLS)**：严格执行行级安全。客户仅限读写本人数据，营养师仅限管理名下签约客户数据。
6.  **技术栈约束 (Tech Stack)**:
    *   **Frontend**: Next.js (Static Export), Tailwind CSS, PWA。
    *   **Backend**: Supabase (Auth, DB, Realtime)。
    *   **Deployment**: Cloudflare Pages。
7.  **Web 端预警**：
    *   **失联预警**：24h/48h/72h 无数据自动触发分级响应。
    *   **库存底线**：剩余量不足 5 天时，Web 端强制红色置顶。

## 2. 灵魂公式 (The Soul Formula)
**WROM 2.0 算法**：
复购指数 **R** 如下：
$$R = Score_{依从性} + Score_{库存水位} + Score_{体感趋势} + Score_{互动活跃}$$
(总分 100 分)

1.  **权重分配**：4 个部分权重分配（4:3:2:1）是基于行业依从性模型。
2.  **维度拆解**：在 Web 管理端，不仅要显示总分，还要支持点击总分查看这四个维度的拆解，让营养师知道为什么这个客户得分低。
3.  **核心 KPI**：将此模型作为系统核心 KPI 的计算标准。

## 4. 辅助维度与业务联动 (Supportive Dimensions & Business Linkage)

除了核心 WROM 2.0 算法外，移动端采集的其他数据用于支撑 Web 端的人工干预与专业分析。

### 4.1 核心生理指标 (The Vitals)
*   **采集项**：体重、体脂率、肌肉量、内脏脂肪等级。
*   **业务逻辑**：这些指标虽然不计入复购分 R 值，但必须在 Web 端生成**“客户健康曲线”**。
*   **商业价值**：作为营养师评估方案有效性的硬指标，对齐展示于体感评分曲线旁，用于“体感 vs 数据”的深度归因。

### 4.2 饮水量管理 (Hydration)
*   **业务逻辑**：作为基础代谢环境的监控项，用于提醒客户保持充足饮水（2.0L+）。
*   **状态反馈**：Web 端应显示客户的日均饮水达成率。

### 4.3 方案阶段深度联动 (Protocol Phase Linkage)
*   **联动位置**：Web 端 -- 客户档案 -- 查看详情 -- 干预配方。
*   **逻辑定义**：
    *   **进度同步**：H5 实时显示 `Protocol Day X`，Web 端对应的方案阶段需高亮当前进度。
    *   **阶段标记**：当某个方案阶段（如：冲击期 14 天）完成时，Web 端干预配方区应自动标记为“已完成此阶段”，并提醒营养师进行下阶段调优。
    *   **跟踪闭环**：营养师必须能通过 Web 端时刻掌握客户处于哪一天的方案进度，确保跟踪的实时性与准确性。

## 5. 激励与预警机制 (Incentive & Alert Mechanism) [v5.0 新增]

### 5.1 社交货币与成就系统 (Achievement Cards)
*   **触发条件**：达成 7/14/21 天打卡里程碑，或减重/体脂达成关键节点。
*   **表现形式**：H5 弹出精美成就卡，支持本地合成分享图片。
*   **隐私保护**：分享卡片自动对敏感信息（全名、具体数值等）进行脱敏处理。

### 5.2 失联分级响应 (Ghosting Prevention)
*   **Level 1 (24h 无数据)**：H5 顶部 Banner 切换为“温馨问候模式”。
*   **Level 2 (48h 无数据)**：触发 PWA Web Push 提醒。
*   **Level 3 (72h 无数据)**：Web 管理端该客户**强制红色置顶**，标记为“🔴 紧急挽回”。

### 5.3 PWA 与消息触达
*   **iOS 适配**：必须包含 iOS 专用的“添加到主屏幕”引导组件。
*   **离线能力**：Service Worker 需支持离线数据排队，网络恢复后自动同步。
*   **实时同步**：基于 Supabase Realtime 实现双端消息毫秒级同步。

### 3.1 依从性 (Weight: 40%)
这是衡量客户是否“听话”的核心指标，直接决定了方案是否能产生效果。

*   **打卡跟踪 (Check-in Tracker)**：作为系统逻辑的“第一推动力”。
*   **强绑定逻辑**：打卡动作必须原子化触发库存扣减，并生成含 `consumed_at` 时间戳的记录。
*   **计算公式**：$Score = \frac{Count_{Actual}}{Count_{Expected}} \times 40$
*   **因子定义**：
    *   $Count_{Actual}$：过去 7 天内，客户在 `check_ins` 表中产生的真实记录条数。
    *   $Count_{Expected}$：营养师在配方中设定的 7 天应打卡总数（如：每日 3 次，则为 21 次）。
*   **边界逻辑**：得分最高 40 分，超过不计入额外总分。若 $Count_{Expected}$ 为 0，该项默认为 0 分并触发“配方缺失”提醒。

### 3.2 库存水位 (Weight: 30%)
这是复购行为的“物理倒计时”，反映了客户手中的“弹药”消耗情况。

*   **打卡触发制**：严禁基于时间的模拟扣减。
*   **原子性保障**：【高压线】严禁在前端本地计算并保存剩余库存。所有库存数据必须以数据库触发器（Database Trigger）产生的 `Inventory_Current` 为准。
*   **触发逻辑**：当 `check_ins` 表新增一条 `is_taken: true` 的记录时，数据库自动查找该客户对应的 `inventory` 表，执行 `quantity = quantity - dosage`。
*   **计算公式**：$Score = (1 - \frac{Inventory_{Current}}{Inventory_{Initial}}) \times 30$
*   **因子定义**：
    *   $Inventory_{Current}$：根据 $Initial - (CheckIn \times Dosage)$ 计算出的当前剩余量。
    *   $Inventory_{Initial}$：营养师最近一次在 Web 端执行“入库/校准”动作后的总量。

### 3.3 体感趋势得分 (Weight: 20%)
核心在于**“进步感”**。采用 10 分制数字化模型（心情、精力、睡眠、肠道反应）。

*   **计算公式**：
    *   $S_{curr} = (Mood + Energy + Sleep + Digestion) / 4$ (本周 7 天所有体感指标的算术平均分)。
    *   $S_{last}$：上周 7 天的平均分。
*   **趋势逻辑**：
    *   **进步奖励**：若 $S_{curr} \ge S_{last}$，$Score = 15 + (S_{curr} - S_{last}) \times 5$ (最高 20 分)。
    *   **退步预警**：若 $S_{curr} < S_{last}$，$Score = 15 - (S_{last} - S_{curr}) \times 10$ (最低 0 分)。
*   **UI 展示**：Web 端应支持点击总分展开四个维度的子曲线，用于深度归因（如：睡眠差导致的心情波动）。

### 3.4 互动活跃得分 (Weight: 10%)
衡量**“信任密度”**。支持“已读/未读”状态追踪与双端强提醒。

*   **已读回执 (ReadRate)**：采用“埋点式”触发。H5 消息组件挂载时，静默触发后端 `is_read: true` 的批量更新。
*   **计算逻辑**：$Score = (MessageCount \times 2) + (ReadRate \times 4)$ (最高 10 分)。
*   **因子定义**：
    *   $MessageCount$：过去 7 天内，客户打卡时填写“体感留言”或主动发信息的次数（1 次得 2 分，3 次及以上拿满 6 分）。
    *   $ReadRate$：过去 7 天内，客户已读的消息数 / 营养师发出的总消息数（100% 得 4 分）。
