# HealthCare Pro 产品与技术核心规范 (PRODUCT_SPEC.md) - v5.2

## 1. 项目定位与核心愿景
*   **定位**：基于 S2B2C 模式的垂直领域 CRM + 健康管理 SaaS 系统。
*   **核心价值**：
    *   **万能模具 (Uni-app)**：一次开发，覆盖小程序双模式与 Web 管理端。
    *   **中央大账本 (PostgreSQL)**：基于角色与租户的数据分发，确保数据安全与业务闭环。
    *   **施工图纸保险柜 (Gitee)**：国产化代码托管，保障商业逻辑资产。

## 2. 架构定义 (Architecture)
本项目采用 **Uni-app + 腾讯云 PostgreSQL (TDSQL-C/CloudBase)** 的全端架构。

### 2.1 组成部分
1.  **Gitee (代码仓库)**:
    *   角色：**施工图纸保险柜**。
    *   任务：存储所有界面逻辑（包括客户看到的小程序、营养师看到的小程序模式及 Web 后台）。
2.  **腾讯云 DB (PostgreSQL)**:
    *   角色：**中央大账本**。
    *   任务：存储全量业务数据，并根据登录身份（Role）分发权限。
3.  **Uni-app (开发框架)**:
    *   角色：**万能模具**。
    *   任务：一次开发，分发出 **小程序 (双模式)** 和 **Web 管理后台**。
4.  **小程序端 (前端 Client/Admin)**:
    *   角色：**全能手机移动店**。
    *   **客户模式**: 打卡、传体感、看方案。
    *   **营养师模式**: 手机接收预警、快速批改、即时回复。
5.  **Web 端 (管理端 Admin)**:
    *   角色：**总店深度监控室**。
    *   任务：仅限营养师使用，用于大屏深度复盘、批量导出数据、复杂配方建模。

## 3. 核心业务逻辑
### 3.1 灵魂公式 (WROM 2.0)
复购指数 **R = 依从性(40%) + 库存(30%) + 体感(20%) + 互动(10%)**。
*   **依从性**: 真实打卡频次 vs 应打卡频次。
*   **库存**: 原子化打卡触发扣减，严禁模拟。
*   **体感**: 数字化心情/精力/睡眠/肠道趋势。
*   **互动**: 留言频率与消息已读率。

### 3.2 角色与数据安全
*   **多租户隔离**: 基于 PostgreSQL 的租户 ID 与角色权限，确保不同机构/营养师数据物理或逻辑隔离。
*   **身份认证**: 微信 OpenID + 手机号，支持极速登录与多端同步。

## 4. 关键交互规范
*   **打卡原子化**: 每一次打卡动作必须实时触发库存扣减并生成带时间戳的记录。
*   **分级预警**: 
    *   24h/48h/72h 无数据分级提醒。
    *   库存不足 5 天红色预警。
*   **双模式切换**: 小程序端根据用户角色自动切换“客户模式”或“营养师模式”。
